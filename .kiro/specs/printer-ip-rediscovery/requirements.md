# 已登记打印机 IP 自动恢复需求

产品版本：`1.0.0` 准正式版维护增强；功能基线：v2 手动优先
更新时间：2026-10-08
前端配套：`farm-v1-release-readiness` R100-15

## 1. 场景和范围

厂内打印机在下班后关机、次日重新开机，DHCP 可能重新分配 IP。服务端需要识别已有设备的新地址，恢复监控，避免管理员重复录入设备。设备地址恢复独立于打印任务派发，不下发打印、加热、运动、取消或急停命令。

## 2. 自动恢复

- Local Edition 默认启用 `farm.discovery.enabled`，基础/dev/test 默认关闭；自动任务仅在 discovery 与全局 monitor 都开启时运行。
- 默认启动 10 秒后进行首次恢复，此后每 5 分钟巡检；监控连续通信失败达到配置阈值时可提前请求恢复，但自动请求共用 5 分钟限频和同一在途任务。
- 目标仅包括开启单台监控且符合监控白名单的已有设备；有效 MAC 与 KLIPPER/RRF 协议是自动确认身份的前提。
- `farm.discovery.subnets` 最多配置 8 个厂内私有 IPv4 `/24` 的三段前缀；为空时从有效目标的已有私有 IP 推断，不能枚举公网或任意用户输入地址。

## 3. 身份和数据边界

- 仅在已登记 MAC、发现 MAC 和协议一致且身份唯一时修改 IP；未知设备不导入，缺失/无效 MAC、协议不支持、设备未找到或身份冲突均逐项说明。
- 旧 IP 能响应也必须核对设备身份，防止 DHCP 将旧地址分给另一台打印机后产生错误监控。开启身份保护且登记有效 MAC 的设备，每次监控和下发密钥/上传/启动/控制命令前都即时匿名核验，不复用旧成功缓存；核验失败拒绝物理动作并保留任务绑定。无有效 MAC 的旧记录维持兼容行为，但不能自动恢复地址。
- 身份核验只使用匿名只读网络信息与精确目标 IP 的 ARP 记录；不得向身份未知地址发送数据库保存的 API Key 或密码。鉴权且跨路由无法取得真实 MAC 时，固定 DHCP 仍不能通过已开启的身份保护；优先调整为服务端与设备处于同一可 ARP 网络。管理员若选择固定 DHCP、关闭 `farm.discovery.enabled` 并手工维护地址，也同时关闭新增身份保护，不应宣称自动恢复已完成。
- 地址批量更新在同一事务中以当前 IP、MAC、协议、监控开关条件校验，支持两台设备交换 IP；锁定匹配规范 MAC 的记录以拒绝扫描期间等价 MAC 新增。任何并发配置变化、锁丢失或地址冲突导致整批更新回滚。
- 只改变 `ip_address`、`connection_status=UNKNOWN`、`updated_at`；保留设备 ID、名称、编号、协议、凭据、位置、监控开关、任务绑定、安全确认及业务状态。提交后刷新列表缓存并清理实时状态/身份缓存，在线状态由后续监控确认。
- 不新增数据库迁移，不删除数据、重建卷或修改生产数据；自动派单仍关闭。

## 4. 管理员手动同步和客户端

- POST `/api/v1/printers/rediscover` 无请求体，异步启动同步；重复进行中请求返回同一 `scanId`。
- GET 同一路径仅查询本实例最近任务，ADMIN 可调用，OPERATOR/匿名不得访问；服务层也校验 ADMIN。
- 前端提供独立“同步设备 IP”入口，普通“刷新”只读取列表；展示范围、进度、计数和逐项结果，2 秒串行轮询，完成刷新列表，失败可重试，卸载清理。
- 任务快照是内存状态，服务重启后为 IDLE，不承诺跨实例查询同一任务；Server Edition 通过 Redis 互斥防重复执行。
