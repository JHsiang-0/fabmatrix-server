# 统一设备模型落地设计与实施约束

状态：实施前设计框架，具体字段、迁移和协议版本须在 T0 冻结；不能把本文件的候选设计当作现有能力。

## 事实基线

| 范围 | 当前事实 | 本任务要求 |
| --- | --- | --- |
| Server | Windows 单实例 SQLite、Klipper/RRF 适配、部分统一观测和现场执行记录 | 完成稳定身份、描述、采集、持久化与安全兼容 |
| 上报 | V1 与已部署的受限 V2，共用当前 MQTT 体系 | 保持兼容；新完整契约不冒充现有受限 V2 |
| Cloud | 独立 MySQL/Flyway、网关授权、快照投影；V5 保存受限观测 | 建立完整模型的消费、持久化和授权查询 |
| 手机 | 已有机器列表和受限详情；新增单设备接口尚需部署 | 接入完整详情和历史，保留旧协议兼容 |

Server 侧不恢复 MySQL、Redis 或 RustFS。Cloud MySQL 是独立云库；两者的迁移工具及数据所有权分别管理。Server 现有文档中仍提到 MySQL 或“独立详情未实现”的段落，以实际代码及本规格阶段核对结果为准。

## 处理顺序和数据流

```text
RRF / Klipper -> Server 协议适配 -> 统一身份、描述、观测与执行
               -> Server SQLite / 本地兼容 API
               -> 完整模型版本化上报 -> Cloud 校验 / MySQL / 授权查询 -> 手机
```

先冻结完整对象、字段矩阵和身份迁移规则，再落地 Server/Cloud 的模型及存储、客户端读取与兼容；完成这些前置检查后才启用完整模型上报。为消除 Cloud 消费端与 Server 上报端的实施依赖，可先在隔离测试中以合成消息实现消费与查询，但不得把合成消息当作现场上报已完成。

## 设计决策门禁

T0 必须产出并评审以下决定，不得通过未经验证的假设直接开工：

1. 对照 `fabmatrix-cloud/docs/data-model/` 的领域字典、固件映射、机器可读 Schema，逐字段标明本轮必交、来源、质量、单位、存储、授权、传输与验收；不支持字段仍要有明确状态。
2. 当前 transport `schemaVersion=2` 已表示受限消息，完整协议使用不冲突的新主版本或显式协商的兼容扩展；冻结版本号、能力协商、topic/ACK、旧消费者行为和回退方案，不能静默改变 V2 语义。
3. 设备 UID、来源实例、现有 cloudPrinterId 的回填与一对一映射；网关重绑、数据库重建/克隆、设备转移的授权和冲突处理；身份不明不自动合并。
4. 完整库存分片的事务提交、去重、缺片超时与恢复：只有全量库存完整确认后才可标记缺席；不能让失败分片删除设备。
5. 事件持久 outbox、去重和保留；状态最新值有界合并；低频描述与高频观测分别限流。冻结字节、内存、磁盘和设备数预算，并以测试数据验证。
6. 明确何时产生告警、谁可确认、保留与删除策略；执行历史与趋势采样的可见权限。禁止跨组织数据泄漏及将现场用户错误映射为云用户。
7. 不改变已执行的 Cloud Flyway 迁移；SQLite 扩展必须在 `LocalSchemaMigration` 及全新初始化两路径一致。新版本号与结构以实施时实际状态为准。

## 兼容与安全

- 保留 LAN 旧接口及 Cloud V1/受限 V2 的语义和授权；Cloud 先支持新旧协议，Server 再显式启用完整上报，手机按实际支持能力切换。
- 设备动作仍由现场控制与安全确认；云只读数据不自动派单、不发控制指令。
- 新增只读 API 在 Service 验证农场/设备边界；unknown、不支持、历史值和过期值须可区分。
- 不上传密钥、API Key、私有地址、原始固件对象或未经授权的路径；日志和测试 fixture 使用脱敏数据。
- Cloud 故障、过大消息和网络中断不能阻塞现场轮询或耗尽队列；运行指标与错误码不包含秘密。

## 分仓库交付

| 仓库 | 职责 |
| --- | --- |
| `fabmatrix-server` | SQLite 迁移、现场模型、固件适配、设备/执行生命周期、本地 API 兼容和网关发送 |
| `fabmatrix-cloud` | 共享模型契约、Flyway 迁移、协议校验、身份/归属、持久化、查询、权限和事件处理 |
| `flutter_application` | API/Repository/领域模型、详情及历史 UI、离线/权限/生命周期处理和真机验收 |

既有两个跨仓库工作区有未提交改动；实施时逐文件审阅和保留，独立运行测试，不以本任务覆盖、提交或部署其他工作。

## 验证与上线顺序

Server 全量测试及 SQLite 新旧库；Cloud `mvnw verify` 和隔离 MySQL/EMQX TLS、重连及迁移；Flutter 静态分析、全量测试和设备详情状态测试。完成后分别进行安装版与手机真机只读验收。真实数据库迁移、服务重启、凭据重绑和物理设备动作应明确目标及影响后执行。回退先关闭完整上报、保留 Cloud 双读和数据，再逐端回退；不能通过删除数据卷替代迁移或回退。
