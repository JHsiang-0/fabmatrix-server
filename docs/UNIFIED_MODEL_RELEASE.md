# 统一设备模型升级与回退

本说明适用于 Server Local Edition、独立 Cloud 和 Flutter 客户端的只读设备模型。完整模型使用 transport `schemaVersion=3`、`modelVersion=2`；Server 的 `FARM_CLOUD_OBSERVATION_V3_ENABLED` 默认关闭。本文不授权修改任何真实数据库、设备或服务。

## 升级前确认

- 确认每个目标的服务实例、数据库、数据目录、网关和部署版本；同一网关身份一次只运行一个代理。先在隔离副本验证，不用删除数据卷或重建数据库代替升级。
- 保留与部署版本对应的 Server、Cloud 和 App 构建产物及配置。Cloud MySQL 必须保存一致性快照，包含 Flyway 历史、账号、农场、设备绑定、事件和遥测；同时保留独立的网关、Broker、TLS 和密钥配置。快照需要在独立库恢复并校验，不能仅以文件存在视为可恢复。
- 停止目标 Server 后保存其 `FARM_DATA_DIR` 的 SQLite 数据和必要配置，以及实际配置的云代理状态目录。SQLite 使用数据库备份 API 创建一致性副本，或在进程完全停止并处理 WAL 后按 SQLite 要求保存完整文件集；运行中只复制主数据库文件可能不完整。安装身份、设备 UID、事件 outbox 和库存版本涉及数据连续性，不能只保留业务表。
- 记录快照时点和恢复后会丢失的后续写入；恢复旧库会回退账号、设备、事件及确认记录，不能与“关闭 V3”混为一谈。凭据和备份按原部署的访问权限保护，不写入 Git 或日志。

## 顺序与验证

1. 先在 Cloud 数据副本验证 Flyway 从当前版本升级到目标版本、账号与农场保留、网关绑定和授权查询；核实 broker TLS、认证与主题 ACL。完成后才升级目标 Cloud，确认健康、迁移状态和旧协议兼容。Flyway 已执行迁移不得改写；本版隔离验收覆盖 V1 到 V16，实际目标版本以构建中的迁移文件为准。
2. 在 Server 数据副本验证 `sqlite-schema.sql` 加 `LocalSchemaMigration` 的启动升级及重复启动，核对身份、设备、任务和 outbox。再升级目标 Server；保持 V3 关闭，确认本地登录、设备列表及现场工作正常，确认旧协议连接 Cloud 正常。
3. 核对 Cloud 已支持 V3、目标网关身份和设备归属后，设置 `FARM_CLOUD_OBSERVATION_V3_ENABLED=true`，重启对应 Server 使配置生效。核查网关状态、Cloud 设备身份、描述与观测版本、数据质量、事件积压和告警日志；手机列表及详情应显示正确的在线、过期和不可用状态。设备动作仍由现场安全流程控制。
4. 分别用授权的 Klipper 与 RRF 设备进行只读核对，记录固件版本、支持字段和未知字段；再验证手机在线、断网、设备离线、移除和恢复。自动告警规则目前未实现，合成告警测试不能作为现场告警能力验收。

## 回退

优先关闭 Server 的 V3 开关并重启对应实例，按实际配置协商回退 V1 或受限 V2；保留数据库、网关凭据和事件 outbox，检查本地业务及旧协议连接。关闭开关不会撤销 Cloud 已保存的数据，也不等于旧版 Cloud 程序可以直接读取升级后的数据库。

如必须回退数据库或程序，先停止相关写入并确定目标、快照版本、恢复顺序及丢失范围；先在独立环境恢复匹配的数据库和程序，验证账号、农场、身份、权限及本地业务，再决定是否操作目标环境。不能直接删除 Flyway 记录、数据卷或设备身份来强制降级。恢复旧快照会丢失快照之后的变更，网关重连和待确认事件也须重新核对。

## 现有证据与未完成项

- Server `LocalSchemaUpgradeIntegrationTest` 覆盖旧 SQLite 升级、重复迁移与身份保持；Cloud 隔离 C1/C2 覆盖 MySQL V1→V16、数据保留、真实 MQTT、V3 兼容和客户端查询。
- 隔离 C1/C2 已将 MySQL V1 升级前快照恢复到独立临时库并核对账号、会话、农场和 Flyway 历史；也将 Server 启动升级前的 SQLite 快照恢复到独立文件并校验完整性及设备记录。两者均是合成数据。
- 隔离 C1/C2 进一步使用离线构建的历史 Cloud `66a94ea` 在恢复的 V1 快照上启动、升级至其 V2 并读取原账号和农场；历史 Server `2729a15` 在恢复的 SQLite 副本上启动，并通过认证接口读取设备。两套旧程序打包时跳过测试；此次连同弱网和 Flutter 共 40 项隔离检查通过。
- 以上测试使用临时数据库及合成设备，不能证明任意历史二进制可对升级后的库直接降级。目标版本的安装包升级、目标数据库恢复、实际设备和手机仍须分别验收，见 [Kiro 任务](../.kiro/specs/unified-device-model/tasks.md)。
