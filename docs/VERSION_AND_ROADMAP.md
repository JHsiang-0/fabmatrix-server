# FabMatrix 版本与路线地图

更新时间：2026-10-08

本文是后端文档的版本解释入口，并与前端 `docs/VERSION_AND_ROADMAP.md` 保持同一结论。

## 1. 当前发布基线

| 项目 | 当前结论 |
| --- | --- |
| 产品名称 | 嘉东三维联动3D打印机实时控制系统 / FabMatrix |
| 产品版本 | `1.0.0` 准正式版 |
| 候选标识 | `v1.0.0-rc.1` |
| 发布形态 | Windows Local Edition：一个本地服务端 + 多个前端客户端 |
| 默认服务端口 | `28081`；HTTP 与 WebSocket 使用同一后端端口 |
| 数据形态 | SQLite/本地文件存储；MySQL、Redis、RustFS 属于 Server Edition 或开发联调依赖 |
| 安装产物 | Windows 服务端安装器；服务端与客户端分别构建、分别部署 |
| 发布依据 | 前端 R100 发布门禁、后端测试/发布脚本和真实 Windows 验收记录 |

1.0.0 准正式版优先保证本地部署、初始化、认证、打印机、文件库、任务中心、看板、WebSocket 和安装器链路可回归。真实 Windows 安装/升级/卸载、真实打印机和长时间运行结果必须以现场验收为准。

## 2. 版本术语映射

| 术语 | 实际含义 | 处理方式 |
| --- | --- | --- |
| `1.0.0` | 当前对外产品版本 | 前端、Electron、服务端、托盘和安装器统一使用 |
| `/api/v1` | HTTP API 的兼容路径 | 保持不变，不改成 `/api/1.0.0` |
| v1 | 基础接口、权限、任务安全、协议和 WebSocket 的历史阶段 | 作为基础能力与验收记录保留 |
| v2 | 手动优先、Local Edition、文件/任务可读性和用户确认流程阶段 | 作为当前实现来源保留；是否进入 1.0.0 由发布门禁决定 |
| v3 | 后台自动派单及高风险批量执行路线 | 1.0.0 不开放，后续单独规划和发布 |

`farm-v1`、`farm-v2`、`farm-v3` 以及任务编号中的版本标识是开发阶段或功能路线，不是产品安装包版本。不要为了统一名称而重命名历史目录。

## 3. Kiro 规格归属

| 规格 | 状态 | 归属 |
| --- | --- | --- |
| 前端 `farm-v1-release-readiness` | 当前发布门禁 | 1.0.0 准正式版联合验收入口 |
| 后端 `.kiro/specs/farm-v2/` | 当前功能实现基线 | 手动优先、Local Edition、任务和文件能力；不等于“发布 v2” |

| `printer-ip-rediscovery` | 源码及自动化回归完成 | 1.0.0 已登记设备 DHCP 地址恢复；前端 R100-15，真实设备/安装升级待验收 |
| `print-history-export` | 源码及自动化回归完成 | 1.0.0 打印历史 Excel/PDF 导出和公共文档生成模块；前端 R100-16，无迁移，真实安装/数据验收待执行 |
| `printer-protocol-and-websocket` | 基础实现、待真实联调 | 协议适配和实时状态 |
| 前端 `farm-v3-batch-dispatch` | 后续规划 | 后台自动派单、批量执行和恢复模型 |

## 4. 文档权威顺序

1. 当前 Java 代码、配置、数据库迁移和自动化验证结果；
2. 1.0.0 发布门禁与真实验收记录；
3. `API_HANDOFF.md` 的接口契约；
4. 具体 Kiro requirements/design/tasks；
5. 根目录 TODO、PROJECT 和历史归档说明。

## 5. 当前不属于 1.0.0 默认交付的内容

- 后台无人确认的自动派单。
- 以 MySQL、Redis、RustFS 为前提的 Server Edition 安装交付。
- 未完成真实设备验证的协议或控制能力。
- 未通过安装器、升级、卸载和数据保留验收的发布结论。

## 6. 新任务维护规则

- 新任务先注明产品版本和 Kiro 规格归属。
- 产品版本统一写 `1.0.0`；历史阶段写“v2 功能基线”等说明，不写成“产品 v2 发布”。
- 接口文档保留 `/api/v1`，并注明它是 API 路径而非产品版本。
- 每个 Task 完成后同步任务状态、接口契约、迁移/发布说明和本索引；不批量重命名历史规格。
